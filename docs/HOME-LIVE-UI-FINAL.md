# ปรับหน้า Home ตาม Master — Issue #48

วันที่ 1 ตุลาคม 2026 · งานพัฒนาและตรวจในสาขาแยก · ยังไม่ merge/deploy เว็บจริง

## สิ่งที่เปลี่ยน

หน้าเดิมมีเมนู ปุ่ม และข้อความจำนวนมากติดอยู่ในภาพรวม รวมทั้งบางหัวข้อถูกลดเหลือ `lg:text-lg` ขณะหัวข้ออื่นขยายตามภาพ ทำให้สัดส่วนไม่สม่ำเสมอ รอบนี้เปลี่ยนส่วนใช้งานเป็นองค์ประกอบจริง และเก็บงานตัวหนังสือตกแต่งเป็นภาพตามที่เจ้าของกำหนด

| ส่วน | รูปภาพ | องค์ประกอบเว็บจริง |
| --- | --- | --- |
| Header | โลโก้เดิม | เมนู บัญชีผู้ใช้ เมนูมือถือ |
| Hero + คำโปรย | รวมเป็นหนึ่งภาพต่อขนาดจอ ทั้งสามบริเวณตัวหนังสือตกแต่งและคำโปรยอยู่ในภาพเดียว | ช่องจังหวัด หมวดงาน คำค้น และปุ่มค้นหา |
| หมวดช่าง | ไอคอนการ์ตูนเดิมแยกไฟล์ทั้ง 7 หมวด | ชื่อหมวด กรอบการ์ด ลิงก์ |
| สถิติ | ไอคอนเดิม คำโปรยลายมือ | ตัวเลขจริง คำอธิบาย พื้นหลัง |
| ช่างแนะนำ | รูปของช่างแต่ละคน | หัวข้อ ชื่อ จังหวัด คะแนน รีวิว หมวดงาน ลิงก์ |
| วิธีใช้งาน/จุดเด่น | ไอคอนแยก ตัวการ์ตูนและคำพูดตกแต่งเดิม | หัวข้อ เลขขั้นตอน คำอธิบาย การ์ด |
| สมัครช่าง | ภาพคนงานและข้อความบนเสื้อ | หัวข้อ คำอธิบาย รายการประโยชน์ ปุ่มสมัคร |
| รีวิว | อวตารระบบเดิม | หัวข้อ ความคิดเห็น คะแนน ลิงก์ช่าง ปุ่มเลื่อน |
| บทความ | ภาพปกแยกจากข้อมูลจริง | หัวข้อ ชื่อบทความ วันที่เพิ่ม ลิงก์ Facebook |
| Footer | โลโก้ ไอคอนสังคม คำโปรยลายมือ | คำอธิบายเว็บ เมนู รายการช่วยเหลือ ปีลิขสิทธิ์ |

- เดสก์ท็อป: ช่างแนะนำ 5 คอลัมน์ วิธีใช้งาน 4 คอลัมน์ รีวิวเลื่อนได้ บทความ 3 คอลัมน์
- มือถือ: แบนเนอร์จัดองค์ประกอบใหม่โดยคงคำเดิม ช่องค้นหาอยู่ด้านล่าง หมวดงาน 4 คอลัมน์ สถิติ/ช่าง/วิธีใช้งาน/จุดเด่น 2 คอลัมน์ บทความ 1 คอลัมน์ ท้ายเว็บเรียงใหม่
- ไม่มี invisible hotspot สำหรับปุ่ม/เมนูอีกแล้ว รูปตกแต่งบางส่วนใช้ SVG viewport ของไฟล์เดิมเท่านั้น
- `เกี่ยวกับเรา` บน Home และท้ายเว็บเลื่อนไปคำอธิบายเว็บจริงใน Footer แทนการย้อนกลับหน้าเดิม
- รีวิวใช้ข้อมูลสาธารณะชุดเดิมและอวตารระบบ ไม่อ่านชื่อหรืออวตารส่วนตัวของผู้รีวิว
- บทความยังใช้รูปทั้งภาพด้วย `object-fit: contain` ตามข้อกำหนดเดิม และลิงก์ไปโพสต์ Facebook จริง
- ข้อความช่วยเหลือที่ยังไม่มีหน้าปลายทางระบุ “เร็ว ๆ นี้” ไม่สร้างลิงก์ปลอม

## จุดแก้ครั้งเดียวสำหรับการปรับครั้งต่อไป

- `app/typography.css`: ฟอนต์/น้ำหนัก/ขนาด/ระยะหลัก
- `HomeSectionHeading.tsx`: หัวข้อหลักทุกส่วนใช้รูปแบบเดียวกัน
- `app/home.css`: จัดหน้าและ breakpoint รวมไว้ที่เดียว โดยใช้ชื่อ class เฉพาะ Home/ Footer
- `public/home/banner-desktop.webp` และ `banner-mobile.webp`: เปลี่ยนแบนเนอร์ได้แยกจากระบบค้นหา
- `public/home/contractor-cta-art.webp`: ภาพสมัครช่างแยกจากข้อความและปุ่ม
- ไอคอนช่างใช้ไฟล์เดิมใน `public/icons/categories/` ไม่มีการเปลี่ยนชื่อหมวดหรือ taxonomy
- SVG `ArtworkDetail` คงตัวหนังสือตกแต่งเดิมจากต้นฉบับ โดยตั้งขอบเขตส่วนภาพที่ต้องการ ไม่ใช้แสดงปุ่มหรือข้อมูล

หัวข้อ “ช่างแนะนำ”, “วิธีใช้งาน”, “ทำไมต้องใช้ หาช่าง?”, “เสียงจากผู้ใช้งานจริง” และ “บทความ & เคล็ดลับ” ใช้ Kanit น้ำหนัก 600 เท่ากัน: 28px desktop, 26px tablet, 24px mobile. เนื้อหาใช้ Noto Sans Thai Variable. การเปลี่ยนฟอนต์ครั้งต่อไปไม่ต้องรื้อระบบ แต่ต้องตรวจการตัดบรรทัดอีกครั้ง

## งานภาพและคำไทย

ใช้ built-in imagegen แก้ภาพจากต้นฉบับเดิมแบบไม่ทับต้นฉบับ แล้วแปลงเป็น WebP โดยไม่เปลี่ยนเนื้อหาภาพ:

1. `public/home/banner-desktop.webp` — 2106×747: รวม Hero + คำโปรย เอาแถบค้นหาที่ติดในภาพออก
2. `public/home/banner-mobile.webp` — 1254×1254: จัดหัวเรื่องด้านบน ตัวการ์ตูนซ้าย บอลลูนขวา คำโปรยด้านล่างในภาพเดียว
3. `public/home/contractor-cta-art.webp` — 2157×729: ลบข้อความ/ปุ่ม/รายการที่ติดอยู่กลางและขวาของภาพสมัครช่าง เก็บข้อความตกแต่งบนเสื้อ

ต้นฉบับเดิมทุกไฟล์ยังอยู่เพื่อย้อนกลับได้ ภาพใหม่เป็น raster ไม่ใช่ไฟล์ออกแบบที่แยกชั้น ถ้าจะเปลี่ยนตัวหนังสือตกแต่งในภาพต้องแก้/เปลี่ยนไฟล์ภาพ แต่ไม่ต้องแก้ระบบค้นหาหรือฐานข้อมูล งานจัดหน้าและตัวหนังสือจริงแก้แยกได้ทันที

ตรวจคำหลักในภาพใหม่: “หาช่างดี สร้างชีวิต”, “ศูนย์รวมผู้รับเหมาไทย”, “ค้นหาช่าง • ดูผลงานได้ • ติดต่อโดยตรง”, “ช่างดี มีทั่วไทย เชื่อมต่อเจ้าของบ้าน กับช่างคุณภาพ”, “หาช่างดี สร้างบ้านดี สร้างอนาคตที่ดีกว่า”, “งานดี สร้างอนาคต ให้ลูกค้า”. เนื้อหาจริงใช้ “ค่าคอมมิชชัน” และปรับคำอธิบายการตรวจสอบให้ตรงกับการตรวจข้อมูลก่อนเผยแพร่ ไม่อ้างว่ารับประกันคุณภาพงาน

## ผลตรวจ

- TypeScript / ESLint ผ่าน; unit tests เดิม 275/275 ผ่าน (21 ไฟล์)
- Production build ผ่าน ด้วย HTTP fixture บน localhost ที่รับเฉพาะ GET/HEAD
- Browser widths: 1440, 1024, 834, 768, 767, 390, 375, 320px
- ไม่ล้นแนวนอน มี header/main อย่างละหนึ่ง หัวข้อหลักทั้งห้าขนาดและน้ำหนักเท่ากันทุก breakpoint
- ค้นหาจังหวัด + หมวด + คำไทย ส่ง GET params ถูกต้อง; เมนูมือถือเปิด/ปิดได้; ปุ่มรีวิวเลื่อนจริง
- ข้อมูลตัวอย่างแสดงช่าง 5 ใบ บทความ 3 ใบ รีวิว 6 ใบ; ไม่มีรูปเสียหรือ JavaScript page error
- `/login`, `/signup`, `/contractors/register`, `/search` เปิดได้และไม่ล้นที่ 320px
- ตรวจภาพ desktop/mobile ด้วยตาและแก้เศษข้อความเดิมที่โผล่จาก crop ของ CTA แล้ว
- กรณีไม่มีข้อมูลผ่านที่ 375px: แสดง empty state ครบ 4 ส่วน ไม่มีรูป/ข้อมูลตัวอย่างหลงเหลือ ไม่มีล้นหรือ JavaScript error; รายละเอียดอยู่ใน `docs/qa/home-live-ui-final-empty/results.json`

## วิธีตรวจซ้ำ

ต้องมี Playwright และ Chromium ในเครื่องตรวจ:

```sh
PLAYWRIGHT_MODULE=/absolute/path/to/playwright \
CHROMIUM_EXECUTABLE_PATH=/absolute/path/to/chromium \
node scripts/qa/home-visual-check.mjs
```

เพิ่ม `--empty` เพื่อ build และตรวจ empty state; `--skip-build` ใช้ได้เฉพาะเมื่อ build ล่าสุดเป็น fixture โหมดเดียวกัน. สคริปต์สร้าง build ทดสอบด้วย localhost config ดังนั้นห้ามนำ `.next` จากการตรวจนี้ไป deploy; ให้ระบบ hosting build ใหม่จาก source ตามปกติ

## ขอบเขตและสิ่งที่ยังต้องตรวจบนระบบจริง

- ไม่เปลี่ยน DB, migration, RLS, auth service, admin API หรือระบบอนุมัติ
- ยังไม่ได้ตรวจการล็อกอิน/สมัคร/อัปโหลดด้วยบัญชีจริงหรือเขียนฐานข้อมูลจริง
- ปริมาณช่าง/ผลงาน/รีวิวใน screenshot เป็น fixture ทั้งหมด ไม่ใช่การยืนยันยอด production
- คง mapping เดิม “รับตรวจบ้าน” ไปหมวด `งานระบบ` ไว้ ต้องตกลง taxonomy แยกหากต้องการเปลี่ยน
- คงพฤติกรรมเดิมของ stats reader ที่คืน 0 เมื่อ query ล้มเหลว รอบนี้ไม่เปลี่ยน data layer
- ความเหมือนของฟอนต์และภาพเป็นการปรับให้ใกล้มาสเตอร์ ไม่ใช่การรับรอง pixel-identical; แบนเนอร์มือถือเป็น composition ใหม่
- PR ใช้ตรวจหน้าตา/merge ต่อ การปิด Issue #48 หมายถึงงานพัฒนาและสำรองเสร็จ ไม่ได้หมายถึงปล่อยเว็บจริงแล้ว
